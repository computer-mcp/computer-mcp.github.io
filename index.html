The access gap

Reasoning is remote.
Your working context is local.

AI clients can plan and reason, but useful work often depends on local repositories, private files, installed tools, desktop applications, and authenticated developer workflows.

A remote shell is too broad. One-off integrations do not scale. Computer MCP puts a deterministic gateway between the client and the machine so every local action has a known route and a bounded authority.

One request, seven checks

From agent intent to a bounded local result.

The gateway routes tools; it does not silently invent authority, select a workspace, or rewrite the requested operation.

  1. 01

    AI client

    ChatGPT, Codex, or another MCP-compatible client requests an exact tool.

  2. 02

    Authenticate

    The connection is bound to a known local, tunnel, or reviewed remote caller.

  3. 03

    Apply profile

    A capability-scoped profile defines what this caller can discover and invoke.

  4. 04

    Resolve scope

    The request targets a registered workspace, tool, CLI, app, or provider.

  5. 05

    Approve risk

    Allowed higher-risk actions pause for explicit, durable consent.

  6. 06

    Execute locally

    A typed adapter runs with bounded input, output, time, and lifecycle resources.

  7. 07

    Return + audit

    The client receives a structured result linked to a redacted audit receipt.

Trust model

Permission is a path,
not a switch.

Computer MCP separates what a caller may ever do from whether a risky allowed action may happen now. Neither tunnels nor approvals bypass the gateway policy.

Read the security architecture ↗
LOCAL

What stays local

Credentials, CLI execution, desktop control, and Codex child processes remain on the registered Mac. Workspace data crosses an active transport only through the bounded result of an invoked tool.

BOUND

What is registered

Workspaces, profiles, callers, capabilities, CLIs, downstream tools, and remote transports are explicit inputs—not ambient authority.

ASK

What needs approval

Allowed mutations, destructive atomics, Codex requests, and other configured higher-risk actions create reviewable consent records.

REFUSE

What it refuses

Unknown tools, workspace escapes, profile expansion, unowned process control, and silent multi-workspace selection fail closed. Logs and diagnostics redact credential-like data.

Complementary by design

Computer MCP is not Codex Remote.

Use the official first-party experience for ordinary remote Codex control. Use Computer MCP when the workflow needs a general MCP-accessible local execution plane across clients, tools, applications, and custom policy.

Status and roadmap

Stable core. Honest edges.

Capability labels describe product maturity, not permission. Every enabled path still passes through the same policy and resource boundaries.

STABLE

Gateway foundation

Workspaces, profiles, local and tunnel connections, builtins, registered providers, governed Git, Computer Use, operation tickets, and redacted audit.

EXPERIMENTAL

Advanced Codex orchestration

App Server, Exec, and MCP lifecycles; Goal passthrough; acceptance runs; handoff diagnosis; and managed child worktrees. Opt-in and disabled by default.

PLANNED

Broader reach

More first-class orchestration UI and platform support beyond macOS. No committed release date.

Know the boundary

  • The signed product currently requires macOS 14 or later.
  • Remote paths depend on user-owned OpenAI or Cloudflare services.
  • Computer MCP cannot terminate an external Codex client it does not own.
  • It does not silently pick a workspace, implicitly push Git, or equate turn completion with accepted Goal completion.
