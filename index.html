怎么连起来

每台电脑，一条自己的连接。

在每台电脑上运行 Computer MCP，再把它接到 ChatGPT 或其他兼容 MCP 的客户端。对话里先选电脑，再选那台电脑上的工作区。

  • Secure MCP Tunnel

    ChatGPT

    通过 OpenAI Secure MCP Tunnel 连接，不需要把本机端口暴露到公网。

  • stdio

    本地 MCP 客户端

    把 App 显示的命令复制到本地客户端；Codex 用户可以核对预览后直接注册。

  • Named Tunnel

    Cloudflare

    通过 Cloudflare Named Tunnel 提供有访问令牌保护的 MCP 地址，供其他远程客户端使用。

权限

每台电脑自己决定允许什么。

在 App 里查看已连接的客户端，选择、降低或结束访问权限。变更立即作用于新的请求。

了解安全模型

  1. 观察

    只允许查看，不修改系统。

  2. 控制 · 受限访问

    只使用你选择的工具、项目和集成，不能任意执行命令。

  3. 控制 · 完全访问

    可以执行命令、访问当前 macOS 用户可用的资源，需要你为这个客户端明确批准。

ChatGPT 请求完全访问 等待确认

仅本次会话 始终允许此客户端

  • 授权默认仅本次会话，“始终允许此客户端”需要单独选择。
  • 完全访问使用当前 macOS 用户的权限；工作区不是沙箱。
  • 会话内的普通本机操作和已验证的官方插件更新无需重复批准；新账号、未验证的持久插件和 macOS 隐私权限需要各自授权。

问题

连接之前。

所有 CLI 都能直接用吗？

先安装外部工具，再注册命令或安装兼容插件。CLI Tree 描述命令、参数和结构化覆盖范围。Computer MCP 不负责安装厂商运行时，也不会把任意可执行文件自动变成完整集成。

CLI Tree 参考
这些能力都是内置的吗？

Gateway 提供共同的连接和权限层。插件打包 MCP、CLI 和 Skills，新安装默认停用，也不授予任何权限。Codex 需要对应插件和本机 Codex。

能力状态
可以操作桌面应用吗？

Computer Use 插件接入原生 CUA，原生辅助功能工具兜底。实际可用性取决于具体操作、macOS 隐私授权和厂商调用者认证；能列出工具不代表已经获得桌面控制能力。

Computer Use 插件
和 Codex Remote 是什么关系？

普通的远程 Codex 控制，优先使用官方体验。Computer MCP 适合还需要本机 CLI、MCP 服务、文件和 Skills，并希望跨兼容客户端组合它们的工作。

会改动我的 Codex 设置吗？

不会。插件通过 swift-codex 提供 App Server 和 Exec 生命周期。Codex 管理自己的配置、provider、MCP、Skills、hooks 和认证。未覆盖的执行参数沿用本机 Codex 配置，包括原生完全访问。原生审批保留自己的决定和作用域，不能批准宿主的票据。

执行有哪些边界？

工作目录和 worktree 不是操作系统沙箱。宿主完全访问和 Codex 原生完全访问使用执行用户的权限。取消请求不代表已经完成或清理；结果不明的写入不会自动重放。Gateway 不能停止不归它管理的外部 Codex 客户端。
