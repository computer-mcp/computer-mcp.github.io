了解安全模型

三种宿主权限模式

只读、工作区操作和本机完全访问是独立设置，不依赖 Profile 名称或接入渠道。高级设置控制能力、工作区与确认策略。本机完全访问不会单独授予工具或启用 Full Shell；Shell 默认关闭。

需要确认，由本机批准

宿主判定的破坏性操作、外部写入和任意执行默认需要本机确认。你在 App 或管理 CLI 中批准；模型提供的 confirm 字段不等于批准，批准也不会扩大授权。

Codex 保留原生执行设置

插件通过 swift-codex 提供 App Server 与 Exec 生命周期。Codex 管理自己的配置、provider、MCP、Skills、hooks 和认证。未覆盖的执行参数遵循本机 Codex 配置，包括原生 Full Access；显式覆盖遵循原生语义。原生审批保留自己的决定和作用域，不能批准宿主票据。

连接前，你可能想知道。

所有 CLI 都能直接用吗？

先安装外部工具，再注册命令或安装兼容插件。CLI Tree 描述命令、参数与结构化覆盖范围。Computer MCP 不负责安装厂商运行时，也不会自动把任意可执行文件变成完整集成。

CLI Tree 参考
这些能力都是内置的吗？

Gateway 提供共同的接入与权限层。插件打包 MCP、CLI 和 Skills，新安装默认停用，也不自动授予权限。Codex 需要对应插件和本机配置，高级编排仍是实验能力。

查看能力状态
可以操作桌面应用吗？

Computer Use 插件接入原生 CUA，原生 Accessibility 工具提供兜底。实际可用性取决于具体操作、macOS 隐私授权与厂商调用者认证；能列出工具不代表已获得桌面控制能力。

Computer Use 插件
和 Codex Remote 有什么关系？

普通的远程 Codex 控制，优先使用官方原生体验。Computer MCP 适合还需要本机 CLI、MCP 服务、文件和 Skills，并希望跨兼容客户端组合这些能力的工作流。

实际执行有哪些边界？

工作目录和 worktree 不是操作系统沙箱。Full Shell 与 Codex 原生 Full Access 使用执行用户的权限。取消请求不代表完成或清理已确认；结果不明的写入不会自动重放。Gateway 不能停止不归自己所有的外部 Codex 客户端。
